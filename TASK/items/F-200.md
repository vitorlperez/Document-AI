# F-200 — Visita pública anônima deixa erro esperado no console

## F-200 | categoria: funcional | severidade: baixa | status: verificado
- Tela: `frontend/app/product-app.tsx:127`
- Passos: 1) Gerar o frontend com `VITE_API_BASE_URL=/api`. 2) Iniciar com `API_UPSTREAM_URL` configurado. 3) Abrir `/` sem sessão. 4) Inspecionar o console do navegador.
- Esperado: A landing page pública renderiza sem erros de console; a ausência de sessão é tratada como estado esperado.
- Observado: Após `de2a3e6`, a landing sem sessão faz somente `GET /api/session` (200 com `null`), exibe o título e não gera erros de console nem de página. No runtime, o upstream 401 foi normalizado só nessa rota; `GET /api/me` continuou 401. O upstream 503 permaneceu 503 em `/api/session` e `/api/me`. Evidências: `TASK/evidence/f200-recheck.json` e `TASK/evidence/f200-proxy-status.json`; screenshot `TASK/evidence/f200-verified.png`.
- (resolvedor) Correção: O bootstrap anônimo em runtime Vinext consulta `/api/session`, cuja BFF normaliza exclusivamente o `401` esperado de `/me` para `200 null`; `/api/me` e demais `4xx/5xx` continuam preservados. A lista de organizações só é carregada após uma sessão autenticada.
- Verificação QA: Reproduzido independentemente em Wrangler e Chromium headless após o commit `de2a3e6`. Landing anônima: heading encontrado, sem alert de falha, 0 erros de console e 0 page errors; `/api/session` retornou 200. Matriz de status: `/api/session` 401→200, `/api/me` 401→401, `/api/session` 503→503, `/api/me` 503→503. F-200 promovido de `corrigido` para `verificado`.
