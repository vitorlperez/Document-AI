# F-200 — Visita pública anônima deixa erro esperado no console

## F-200 | categoria: funcional | severidade: baixa | status: corrigido
- Tela: `frontend/app/product-app.tsx:127`
- Passos: 1) Gerar o frontend com `VITE_API_BASE_URL=/api`. 2) Iniciar com `API_UPSTREAM_URL` configurado. 3) Abrir `/` sem sessão. 4) Inspecionar o console do navegador.
- Esperado: A landing page pública renderiza sem erros de console; a ausência de sessão é tratada como estado esperado.
- Observado: `loadSession` usa a resposta 401 de `/me` como controle de fluxo (`if (!(caught instanceof ApiError && caught.status === 401))`), mas o navegador ainda registra `Failed to load resource: the server responded with a status of 401 (Unauthorized)`. Evidência runtime adicional: `TASK/evidence/browser-results.json`, caso `desktop-public`.
- (resolvedor) Correção: O bootstrap anônimo em runtime Vinext agora consulta `/api/session`, cuja BFF normaliza exclusivamente o `401` esperado de `/me` para `200 null`; `/api/me` e demais `4xx/5xx` continuam preservados. A lista de organizações só é carregada após uma sessão autenticada. Validado com testes unitários, build `VITE_API_BASE_URL=/api`, runtime Wrangler e Playwright headless sem erros de console, página ou HTTP na landing anônima. Aguarda verificação independente de QA.
