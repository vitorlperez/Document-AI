# F-212 — Callback ClickUp de produção com prefixo do proxy

## F-212 | categoria: integração | severidade: alta | status: callback ativo; validação operacional parcial
- Responsável pela consolidação: pane-501; implantação: pane-500 (`h-l7`); branch local: main; documentação publicada em `docs/f212-production-verification`.
- Sintoma original: autorizar ClickUp em produção retornava 404; local funcionava.
- Causa confirmada: `CLICKUP_OAUTH_REDIRECT_URI` usava `/data-sources/clickup/oauth/callback` no frontend; nesse host o proxy só encaminha `/api/data-sources/clickup/oauth/callback`, removendo `/api` ao chamar a API.
- Correção **ativa**: runtime API confirma `PUBLIC_APP_URL` + `/api/data-sources/clickup/oauth/callback`. Frontend `18cbbdd1-9996-4d0b-af4b-3ef375fbc483` e API `f8311dd2-0bed-4154-8245-2d8b0887444d`, ambos `SUCCESS`, commit `2112c8a`. Readiness 200; callback anônimo chega à API e retorna 401 `authentication required`, sem consumir código real. Não é prova da validação de state nem OAuth completo.
- Contrato configurado: segredo novo compartilhado server-side (criado por pane-500); frontend `AUTH_CLIENT_IP_SOURCE=railway`; `ENVIRONMENT=production`; somente os 2 hosts privados reais do frontend (/32 IPv4, /128 IPv6), conferidos por DNS e conexão TCP depois do deploy. API usa `UVICORN_PROXY_HEADERS=false`; execução da CLI uvicorn instalada comprova `proxy_headers=False`, equivalente ao `--no-proxy-headers` do runbook.
- Validação independente: 8/8 checks HTTP; login personalizado visível em 1280/390 px sem overflow ou alertas; 104 testes backend e 9 frontend; build vinext passou. Ingress público sobrescreve `X-Real-IP` falso; API direta recusa contexto forjado com 403.
- **Pendência real de confiança:** acesso pela rede privada ao frontend contorna o ingress público. POST privado com `X-Real-IP` falso e senha vazia retorna 400 após passar pelo HMAC e cria bucket Redis do IP falso (0 → 1). A premissa de acesso exclusivamente via edge em `frontend/app/api/proxy-headers.mjs:22` não está garantida para processos do mesmo ambiente. Não demonstrado bypass pela internet. Não houve chamada WorkOS. Código de segurança adicional exige revisão independente antes de publicação; nenhuma correção desse tipo foi publicada nesta verificação.
- **Pendência real de runtime:** Worker ativo `0774aa91-4b74-4afb-8f3e-718c316a7ddb` ainda não recebeu as variáveis preparadas; `get_settings()` falha (exit 1), e logs recentes têm 9 ocorrências do erro de contrato proxy. Tarefas de reconciliação usam Settings. Beat ativo continua como agendador sem construir Settings; construção direta falha por `DATABASE_URL` ausente. MCP não está implantado.
- Limite operacional: novo deploy frontend pode mudar os peers e exigir novos CIDRs observados. Frontend não tem healthcheck configurado; API tem `/health/ready`. Autodeploy de main está ligado e sem watch paths, portanto documentação foi publicada em branch própria; merge/push main aguarda proteção operacional contra novo deploy.
- Usuário deve permitir a URL completa `https://frontend-production-e02d.up.railway.app/api/data-sources/clickup/oauth/callback` no app OAuth ClickUp e clicar **Conectar** novamente na sessão real; não reutilizar link de autorização antigo. Nenhum OAuth real/e-mail/conta de terceiros foi usado.
