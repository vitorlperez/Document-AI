# F-212 — Callback ClickUp de produção aponta para rota sem o prefixo do proxy

## F-212 | categoria: integração | severidade: alta | status: correção configurada, ativação bloqueada
- Responsável: pane-500; branch: main; pedido recebido em 2026-10-08.
- Sintoma: autorizar o ClickUp em produção retorna 404; local funciona.
- Causa confirmada: `CLICKUP_OAUTH_REDIRECT_URI` da API usa o host do frontend com `/data-sources/clickup/oauth/callback`. Nesse host a rota existe em `/api/data-sources/clickup/oauth/callback`; o proxy remove `/api` ao encaminhar ao backend.
- Reprodução sem credenciais: GET no frontend em `/data-sources/clickup/oauth/callback?code=test&state=test` retorna 404. Com `/api`, retorna 401 de autenticação da API, confirmando a rota. Nenhum código OAuth real foi consumido.
- Hipótese testada: falta `/api` na variável de produção; a implementação do callback e o proxy existem. Referências: `backend/app/api/integrations.py:376`, `frontend/app/api/[...path]/route.ts:24`, `docs/deployment/railway-production.md:56`.
- Correção aplicada na configuração Railway: variável alinhada com `PUBLIC_APP_URL` + `/api/data-sources/clickup/oauth/callback`, usando `--skip-deploys`. Releitura confirma igualdade exata. Nenhum deploy foi disparado; a API em execução continua com sua configuração anterior até um deploy saudável. Verificar também que o app OAuth ClickUp permite a URL completa.
- Bloqueio independente: último deploy da API falha no pre-deploy Alembic porque `AUTH_PROXY_SECRET` e `AUTH_TRUSTED_PROXY_CIDRS` estão ausentes. A API anterior permanece respondendo. Não contornar as validações de segurança nem inventar CIDRs.
