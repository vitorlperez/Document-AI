# F-036 - Perfil de deploy gratuito para piloto

**Status:** done

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md` §§7, 10, 14–15; F-035's production deployment profile; user decision to put the MVP online temporarily with free managed services, keeping a later Oracle/Google migration open.
- User outcome: deploy a testable public pilot without being blocked by the current capacity shortage for Oracle Always Free compute.
- Non-goals: create third-party accounts, buy/register a domain, copy existing local data, guarantee an SLA, run a hosted worker for free, or replace the Oracle deployment profile from F-035.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Use two Render free Docker web services for the browser app and API. | Product | approved | The user approved the temporary free-services path. Separate web services preserve the API/frontend boundary and are disposable. |
| Use Supabase PostgreSQL with pgvector and Upstash Redis, supplied as URLs. | Product | approved | The app already depends only on PostgreSQL/pgvector and Redis protocols; managed URLs avoid exposing a database or queue. |
| Keep the Celery worker on the developer's Docker host for the pilot. | Product | approved | Render does not provide free background-worker instances. Jobs remain asynchronous; they wait in Redis while the local worker is stopped. |
| Require `app.<parent-domain>` and `api.<parent-domain>` before testing authenticated flows. | Engineering | approved | Credentialed browser cookies remain same-site under one registrable parent while CORS stays limited to the configured app origin. The concrete domain is a deployment input, not committed configuration. |
| Keep the Oracle compose profile untouched. | Engineering | approved | This is a reversible pilot profile, not a replacement for F-035. |
