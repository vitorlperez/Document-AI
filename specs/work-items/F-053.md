# F-053 - Ícones de integração nas raízes da biblioteca

**Status:** validating

## Source and outcome

- Source specification: `specs/adr/ADR-0006-company-library-projection.md`; `specs/001-mvp-document-intelligence.md`, F3 and product navigation.
- User outcome: integration roots are visually identifiable in the conversation library tree and the Library page; opening a root continues into its existing folder/file hierarchy.
- Non-goals: changing provider navigation, indexing scope, retrieval behavior, library permissions, or adding integrations.
- Follow-up from screenshot: the UI may be served by a backend version that does not yet include `source_provider`; known source-root names now provide a frontend fallback.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Expose the provider key on source-root library nodes and use a shared icon component in the frontend. | Implementation | Approved | `source_id` maps to a tenant-scoped `DataSource`; explicit provider keys avoid coupling icons to display names. |
