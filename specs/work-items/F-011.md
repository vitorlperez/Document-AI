# F-011 - Configuração de credenciais de conectores no Docker

**Status:** done

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md` §12 and §13; ADR-0001 and ADR-0002.
- User outcome: root `.env` credentials consistently reach all backend containers, so login, Drive OAuth and invitation delivery can be configured without changing source code.
- Non-goals: provision external accounts, store secrets in the repository, change authorization behavior or implement a new connector.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Environment source | User | Approved | Docker Compose reads developer/deployment values from root `.env`; secrets remain outside version control. |
| Callback defaults | Implementation owner | Approved | Local Google callback has a safe documented default; production overrides it with its deployed HTTPS URL. |

## Acceptance criteria and test matrix

| Criterion | Test layer | Evidence |
| --- | --- | --- |
| Given a developer supplies WorkOS, Google OAuth, encryption and invitation variables in `.env`, when Docker Compose resolves the stack, then API, worker and migration services receive the same values. | Compose configuration | `docker compose config` with non-secret sentinel values |
| Given no Google redirect URI is supplied locally, when Docker Compose resolves the stack, then it uses the documented `localhost:8000` callback without a secret. | Compose configuration | `docker compose config` |
| Given production deploys its own public URL/callback, when values are supplied, then Compose does not hard-code `localhost`. | Compose configuration | Override assertion in resolved config |

## Validator report

- Blocking: none.
- Important: none.
- Suggestions: never print `docker compose config` with a real `.env` in CI logs, because Compose resolves values before rendering.
- Independent evidence: validator reran `docker compose --env-file /dev/null config --quiet`, checked sentinel overrides across migration/API/worker, and confirmed local defaults without an `.env` file.
- Gate decision: PASS — all credential settings propagate without secrets committed to the repository.
