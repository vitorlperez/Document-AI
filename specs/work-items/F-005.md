# F-005 - Folder-scoped textual search

**Status:** done

## Source and outcome

- Source specification: spec 001 §§3, 6–11, 14–15 and the indexed-document lifecycle in F-004.
- User outcome: a Member finds matching document titles and extracted chunks within exactly one selected workspace folder.
- Non-goals: semantic/vector retrieval, answer generation, cross-folder/company search, snippets from removed/failed documents and Google Drive live queries.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Use PostgreSQL full-text search (`simple` configuration), ranking title and extracted chunk text; API pagination is bounded to 50 results. | Engineering | Approved implementation choice | Keeps retrieval in PostgreSQL and is language-neutral for the pilot; no protected product decision changes. |

| Criterion | Test layer | Evidence |

| Given an outsider, inactive member, forged organization, or another folder, when searching, then deny access or return no foreign content. | API/unit | `test_text_search.py::test_search_is_scoped_to_member_organization_and_workspace_folder`; API cross-tenant case |
