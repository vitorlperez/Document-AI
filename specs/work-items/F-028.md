# F-028 - Gestão de arquivos sincronizados

**Status:** done

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md`, F3 — processamento assíncrono, idempotência e controle de documentos elegíveis no escopo selecionado.
- User outcome: Owner/Admin consegue gerenciar os documentos sincronizados por escopo, removendo somente a cópia indexada ou solicitando reprocessamento com novos chunks e embeddings.
- Non-goals: editar, remover ou mover arquivos no Google Drive; permitir Member gerir documentos; remover uma cópia que pertença a outro escopo; criar um worker/serviço novo.

## Acceptance criteria and test matrix

| Criterion | Test layer | Evidence |
| --- | --- | --- |
| Given an Owner/Admin selects a synchronized file in the library, when they remove it and confirm, then only that UUID document and its chunks are removed from that workspace index and the Drive original is untouched. | API + service | Document/chunk absence and audit action. |

## Impact assessment

- API/data: adds scoped document-management endpoints; no migration. Local document/chunk deletion is intentional, user-confirmed and audited.
- Authorization/tenant: endpoint requires Owner/Admin, validates both workspace and Document under the same `organization_id`; UI is hidden for Members.
- Failure states: missing/foreign document never reveals data; unavailable dispatcher leaves a durable queued job as the existing sync contract does.
- Performance/observability: reprocess performs the existing full discovery job but only the chosen document bypasses the unchanged-content shortcut; actions create safe audit records without names/text/tokens. The management action and sync enqueue serialize on the workspace row, preventing interleaved local mutations and active-job checks.
