# F-066 - Logout sem redirecionamento de retorno WorkOS

**Status:** done

## Fonte e resultado

- Usuário relata que clicar no ícone de logout mostra login ainda sob `/companies/...` e depois erro `app-homepage-url-not-found` do WorkOS.
- F-034 definiu encerramento da sessão local e remota, usando URL de logout do WorkOS. A URL de retorno do provedor depende de configuração externa de homepage/logout redirect.
- Resultado aprovado pelo pedido atual: encerrar ambas as sessões no backend e navegar diretamente à rota pública `/login`, sem preservar a rota da empresa no histórico do navegador.

## Decisões e impacto

- Usar a API oficial WorkOS de revogação de sessão para o ID `sid` já armazenado; manter somente o cookie opaco da aplicação.
- Decisão durável registrada em `specs/adr/ADR-0010-workos-server-side-logout.md`, substituindo o redirecionamento remoto previsto em F-034.
- Em falha de WorkOS, revogar a sessão local e forçar autenticação fresca no próximo login. Não expor o ID da sessão nem detalhes da falha.
- Nenhuma mudança de banco, organização, permissões ou API de dados; somente o valor do `redirect_url` de logout.
- Módulos: `backend/app/identity/auth.py`, `backend/app/api/auth.py`, `frontend/app/product-app.tsx`; testes de auth em `backend/tests/api/test_google_integrations.py`.
- Validação independente somente leitura após a implementação.

## Critérios e testes

- Sessão com `sid`: logout revoga a sessão local e a sessão WorkOS e retorna `/login` da aplicação.
- Sessão legada sem `sid` ou indisponibilidade de WorkOS: logout local funciona e o próximo login exige reautenticação.
- Frontend substitui a entrada do histórico ao sair da rota da empresa.
- Testes focados de API e identidade: 53 passaram. Suíte completa do backend: 272 passaram, 6 ignorados. Ruff check e TypeScript passaram.
- Build frontend passou. Rebuild local de API e frontend passou; API saudável, `POST /auth/logout` sem sessão retorna `http://localhost:3000/login`, e `/login` responde HTTP 200.
- Validação independente somente leitura: sem bloqueios; 34 testes focados passaram e assinatura `revoke_session(session_id=...)` foi conferida no SDK instalado.
- Logout real de uma sessão autenticada pelo WorkOS não foi executado; os testes de API usam gateway simulado para evitar encerrar a sessão ativa do usuário.
