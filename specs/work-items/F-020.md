# F-020 - Operação e consulta na Biblioteca da Company

**Status:** done

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md` F3/F4, `ADR-0006`, and the user request for visible sync progress, text search in the Library, and an AI entry point.
- User outcome: from the Company Library, a member can see recent synchronization state, find integrated folders/files by name, and ask the AI after explicitly choosing an indexed knowledge scope.
- Non-goals: company-wide RAG, full-content search across scopes, a progress percentage without worker telemetry, live provider browsing, or changes to the uniform-access model.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| Library text search searches safe folder/file names and source metadata only, scoped to the organization. | Product + engineering | Approved | It helps navigation without introducing unscoped extracted-content retrieval. |
| An AI question from the Library requires a member-selected ready workspace folder and uses the existing scoped question endpoint. | Security + product | Approved | `ADR-0006` and MVP F4 require organization + workspace filtering before retrieval/LLM calls. |
| A `partial_failure` workspace remains selectable because it can retain valid indexed documents; queued, syncing and failed scopes are excluded. | Product + engineering | Approved | Matches the existing `QuestionService` readiness rule. |
| Sync progress is an observable job phase (`queued`, `syncing`, terminal state) with polling for active jobs, not a fabricated percent complete. | Engineering | Approved | Existing jobs do not persist item totals; phase is truthful and immediately useful. |
| --- | --- | --- | --- |

## Acceptance criteria and test matrix

| Given a source has queued/syncing/recent jobs, when a member opens the Library, then it sees only its Company job phases and active phases refresh without a page reload. | API + UI build | Job list contract and polling review |
| Given a member searches a term from the Library, when matching safe node names exist, then it receives matching folder/file metadata only from its Company. | Unit + API | Positive, blank and cross-organization cases |
| Given a member asks the AI from the Library, when it selects a ready workspace context, then the request uses that context and returns the existing citation-bearing response. | API + UI build | Existing scoped endpoint contract |
| Given no ready context is selected, when a member attempts an AI question, then the UI does not issue a question request. | UI build/manual inspection | Disabled state |
| Given another Company's workspace/job/node UUID, when requested, then no metadata, job status, search result, or AI context is disclosed. | Unit + API | Membership/tenant isolation tests |
