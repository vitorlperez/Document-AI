**Status:** done

## Source and authorized decisions

User explicitly requests auditing/fixing Copilot's multi-tool questions, whole-tool context (Google Drive), future cross-tool answers with tool/file attribution and UI improvements. This supersedes spec 001's single-folder-only question limitation, retaining organization isolation and explicit authorized workspace-folder set before ranking/generation.

Scope: query a single folder, all indexed eligible folders of one provider/tool, or all indexed eligible folders across current organization. No live provider searches, newly integrated connectors or automatic expansion of synchronized Drive permissions. “All” means the currently synchronized/indexed corpus; disconnected sources retain already indexed content per existing retention policy. Partial coverage must be honest. No schema migration or saving broad-scope questions into a single-folder saved-query record.

## Findings

Copilot added organization endpoint + multi-folder retrieval + provider citation metadata, but folder selector/composer gating and empty/saved states remain single-folder-oriented. Raw provider IDs appear in citations. Organization endpoint selects folder models directly and lacks route-level isolation/negative regression coverage. Provider metadata join needs explicit organization filters. Broad corpus inventory/ranking must not imply exhaustive reading or count duplicate overlapping documents as independent evidence.

## Contracts / design

Existing POST /workspace-folders/{id}/questions stays compatible. POST /organizations/{id}/questions accepts scope provider with provider key or organization without provider. Invalid combinations must fail safely. Multi-folder retrieval explicitly authorizes every folder; no cross-org provider metadata/content. Citations include source_provider for broad scopes and ideally all scopes without breaking old folder response contract. Friendly names displayed UI; raw identifiers retained data.

No answer fabricated when index or embeddings unavailable. Return explicit safe retrieval status; UI shows eligible coverage and pending folders rather than claiming live exhaustive tool access. Global relevance ranking bounded to existing MAX_CITATIONS and query/provider calls; avoid unnecessary duplication from overlapping scopes. Preserve existing structured safe logs and usage limits.

- UI responsive and accessible; same existing compact chat dimensions.
