# F-014 - Escopos configuraveis de sincronizacao do Google Drive

**Status:** complete

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md`, F3, F4, ADR-0002 and ADR-0003.
- User outcome: after connecting Google Drive, an Owner or Admin can form one knowledge workspace from several recursive folders, files directly in Drive root, or an explicit whole-Drive mode, then start one safe reconciliation.
- Non-goals: individual-file picking, Drive writes, a document previewer, shared Drive permission administration, automatic continuous sync, or changing the one-workspace-folder boundary of search/RAG.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| A `WorkspaceFolder` remains the logical search/RAG boundary and may have multiple Drive selections. | Product + implementation | Approved | Preserves F4 while avoiding separate duplicate indexes for a multi-folder selection. |
| `selected` mode accepts one or more recursive folders and optional direct-root files; `all_accessible` is exclusive. | Product + implementation | Approved | Makes the cost/privacy impact of all Drive explicit. |
| Discovery unions selections and deduplicates by Google `external_file_id` before extraction. | Implementation | Approved | Prevents parent/child selections from multiplying download, chunks or embeddings. |
| Existing single-folder workspaces are migrated additively to one `folder` selection. | Implementation | Approved | Safe rollout; no customer documents are deleted. |

## Acceptance criteria and test matrix

| Criterion | Test layer | Evidence |
| --- | --- | --- |
| Given an Admin with a connected source, when they submit two folder IDs with uniform-access confirmation, then one workspace is created with two selections. | API | Tenant-scoped request test |
| Given parent and child selections, when discovery completes, then every external file is extracted at most once. | Unit | Provider union/deduplication test |
| Given `include_root_files`, when discovery runs, then only files whose direct parent is `root` are added. | Unit | Provider root selection test |
| Given `all_accessible`, when folders or root files are also submitted, then the request is rejected without a workspace. | API | Negative contract test |
| Given a forged folder ID, missing confirmation, a Member, or another tenant's source, when a scope is submitted, then no selection is persisted and no remote metadata leaks. | API | Authorization and validation tests |
| Given a source requires reauthentication or remote discovery fails, when the job runs, then it fails safely and the last complete index remains available. | Existing worker/integration behavior | Targeted regression suite |
