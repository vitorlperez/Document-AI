# F-030 - Layout de tela cheia e alertas temporários

**Status:** done

## Source and outcome

- Source specification: pedido direto do produto para as telas de Consultas e Biblioteca.
- User outcome: os dois espaços de trabalho usam toda a altura útil do navegador, mantêm o cabeçalho acessível e permitem rolagem interna quando o conteúdo ultrapassa a janela. Mensagens de sucesso e erro são notificações temporárias no canto superior, com barra de progresso e fechamento manual.
- Non-goals: alterar regras de sincronização, APIs, persistência de notificações ou os fluxos de autenticação.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Aplicar layout de altura de viewport somente aos workspaces de Consultas e Biblioteca | Product | approved | Páginas de onboarding, equipe e integrações continuam com rolagem normal. |
| Usar toast não bloqueante de seis segundos para sucesso e erro | Product | approved | Feedback visível sem interromper a consulta; o botão fecha imediatamente e a barra representa o tempo restante. |

## Validator report

- Blocking: None.
- Important: None for the requested initial toast/display behavior. A repeated operation that sets exactly the same message while its toast is still visible does not reset the six-second timer, because React can coalesce an identical string state update. This is a narrow follow-up scenario rather than a regression in the initial notification flow.
- Suggestions: Represent alerts with an event id/timestamp in addition to the message if repeated identical notifications must each receive a new full six-second lifetime. With `prefers-reduced-motion`, the timer still dismisses at six seconds but the progress bar intentionally does not animate.
- Independent evidence: Static review confirms `fillViewport` is restricted to `company` (Consultas) and `library`; Shell uses `h-dvh`, a shrink-free header, a flex/min-height-zero content area and `.workspace-shell` internal vertical scrolling. `NotificationToast` is fixed at the upper-right, has semantic `alert`/`status` roles, manual close, a six-second progress animation and `setTimeout(..., 6000)` cleanup. `dismissAlert` retains the existing OAuth query-marker cleanup. Validator reran frontend lint and production build successfully.
- Gate decision: Approved. Manual visual validation with an authenticated browser session remains recommended for responsive viewport dimensions, but no blocking implementation issue was found.
