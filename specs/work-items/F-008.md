# F-008 - Interface web do MVP Document Intelligence

**Status:** blocked

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md`, especially F2–F5 and the API contracts.
- User outcome: a responsive web workspace where authenticated organization members select a work folder, ask questions or search its indexed documents, inspect citations, save queries, and where admins can begin a Google Drive connection and sync.
- Non-goals: changing document retrieval, LLM behavior, Drive permissions, data models, or adding unsupported external providers.

## Acceptance criteria and test matrix

| A member selects a folder, asks a question, and the answer is shown with citations and source links. | UI/API integration | Successful build; response and citation rendering inspected. |
| A member searches indexed documents and sees only the selected folder's result state. | UI/API integration | API client constructs the scoped search request. |
| A member can save, run, and delete their own saved query. | UI/API integration | API client uses the scoped saved-query endpoints. |
| An Admin can start Drive connection, select a folder only after uniform-access confirmation, and start sync. | UI/API integration | API client uses established admin endpoints and presents explicit confirmation. |
| Authentication, API, unavailable folder, and insufficient-evidence failures explain the recovery action without disclosing content. | UI negative paths | Error-state review and focused build. |
