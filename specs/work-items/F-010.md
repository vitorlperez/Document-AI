# F-010 - Company switcher, RBAC e operação de pastas

**Status:** done

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md` F1–F5, frontend product audit and ADR-0004.
- User outcome: a signed-in person reaches a complete Company → folder → evidence journey without manual IDs; the UI differentiates Company roles and platform staff without weakening tenant isolation.
- Non-goals: custom Company roles, document ACLs, team hierarchy, a new Company table, additional source providers, billing or unrestricted staff access.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| Company model | User | Approved | `Organization` remains the persistence model; Company is product terminology. |
| Multi-company access | User | Approved | User may have memberships in several Companies and selects active context. |
| Member administration | User | Approved | Only Owner manages members, invitations and role changes. |
| Public IDs | User | Approved | All persisted IDs exposed in browser routes and API calls are UUIDs; no internal sequential identifiers. |
| Staff access | Product | Approved | `platform_staff` is distinct from memberships; access is explicit, expiring and audited per Company (ADR-0004). |
| Staff content boundary | Product | Approved | Pilot staff access is metadata-only: no document text, citations, source links, saved queries, search or question generation. |

## Acceptance criteria and test matrix

| Given a signed-in user, when they open the product, then they see only active Companies to which they have a membership and enter one through its UUID route. | API/integration + UI | Positive and cross-company-denial tests; build |
| Given an Owner, when they manage a Company team, then they can list/invite/change roles/remove members; Admin and Member get 403 from every equivalent API. | API/integration | Role matrix and audit evidence |
| Given a Member, when they select a Company UUID and folder UUID, then the folder dashboard, search, question and saved-query routes remain scoped to that Company and folder. | API/integration + UI | Cross-tenant/cross-folder denial and route-contract tests |
| Given an Admin or Owner, when they connect Drive, then they can select a remote folder after explicit uniform-access confirmation, start a sync and see its state/failures; a Member cannot. | API/integration + UI | Role negative paths and UI build |
| Given a platform staff member with an active UUID Company grant, when they open support mode, then they see metadata for only the granted Companies, an access banner and expiry; without a grant or after expiry they receive 403. | API/integration + UI | Grant, expiry, cross-Company and audit tests |
| Given a platform staff member, when they are in support mode, then document text, links, saved queries, search and question APIs remain unavailable. | API/integration | Explicit metadata-only negative tests |
