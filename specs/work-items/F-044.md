# F-044 — Inicialização resiliente do container frontend

**Status:** done

## Diagnóstico

O serviço local usava `npm run dev` como processo principal. Após um `SIGTERM`, o shell do npm podia deixar o processo Vinext e o arquivo `.vinext/dev/lock.json` em estado residual. O próximo start falhava com `Another vinext dev server is already running` e o container terminava com código 1.

## Correção

O `frontend/Dockerfile` agora executa `node scripts/run-framework.mjs dev ...` diretamente como PID 1. Assim o Docker encaminha sinais ao servidor e o Vinext libera o lock no encerramento.

## Evidência

- `docker compose up -d --build frontend`: concluído.
- `docker compose restart frontend`: container voltou `Up` sem erro de lock.
- `curl -I http://localhost:3000/`: `HTTP/1.1 200 OK`.
- `npm run lint`: executado após a alteração; avisos existentes não bloqueantes permanecem fora deste ajuste.
