# F-068 - Preparação de deploy de produção na Railway

**Status:** done

## Fonte e critérios

- Pedido do usuário para preparar o ambiente da aplicação para deploy de produção na Railway.
- Fonte arquitetural: `specs/001-mvp-document-intelligence.md`, seção 14.
- Frontend, API e worker são serviços separados; PostgreSQL e Redis ficam privados no mesmo ambiente.
- API executa migrações uma vez por deploy, antes do novo processo servir tráfego.
- Frontend recebe a URL pública final da API no build; login e OAuth usam origens públicas corretas.
- Banco e Redis não são expostos; há instruções de backup, restauração e validação funcional.

## Decisões e limites

- Escolha da Railway já autorizada pelo usuário. Preparar código e instruções; criação de recursos pagos e publicação dependem de domínio, região, orçamento e credenciais da conta.
- API e worker usam a mesma imagem Python. O worker inicia com concorrência limitada a 1 para o primeiro dimensionamento.
- O banco mantém dados e embeddings conforme o modelo atual; nenhuma migração de esquema de domínio.
- Dono da implementação: compatibilidade PostgreSQL em `backend/` e documentação de configuração Railway em `docs/deployment/`.
- A Railway descontinuou Config as Code para novos serviços. O projeto deve ser configurado no painel e posteriormente importado para Infrastructure as Code com `railway config pull`, após a criação da conta/ambiente.
- Validador independente: somente leitura após a implementação.
