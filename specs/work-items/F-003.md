# F-003 - Google Drive OAuth and workspace folders

**Status:** done

## Source and outcome

- Source specification: [001-mvp-document-intelligence.md](../001-mvp-document-intelligence.md), sections 3–9, 11–15; [ADR-0002](../adr/0002-google-drive-connection.md).
- User outcome: an Owner/Admin connects a Google Drive read-only, sees folders available to that connection, and explicitly selects eligible shared work folders for the organization.
- Non-goals: document discovery, downloads, extraction, queues, sync, inherited Drive ACLs, write operations, other providers, frontend UI and production Google credentials.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Google Drive is the sole source provider and uses server-side authorization-code OAuth. | Product spec | Approved | ADR-0002 |
| Use the restricted read-only Drive scope, never a write scope. | Implementation owner | Approved | ADR-0002 |
| Encrypt source credential JSON with the deployment-provided Fernet key; no token is API/log/test data. | Implementation owner | Approved | ADR-0002 |
| Owner and Admin manage sources/folders; Member is denied. Folder eligibility is an explicit Admin confirmation, not Drive ACL mirroring. | Product spec | Approved | Spec §4 / ADR-0002 |

### Impact and failure states

- **Data:** `data_sources`, `oauth_connection_states` and `workspace_folders`, all organization-scoped. Credentials and OAuth states are stored only as ciphertext/hash; a source has `connected`, `reauth_required` or `disconnected` state.
- **API:** start/callback/list source/list folders/select folder. Every source/folder lookup filters `organization_id`; a generic 401/403/404 is returned without provider tokens or remote error payloads.
- **Authorization:** active Owner/Admin required to manage integrations. Member or a user from another organization cannot see or modify a source or folder.
- **Observability:** structured events have provider, action, result and elapsed time. They exclude authorization code, OAuth state, token, remote file name and URL.
- **Performance:** local state/cipher/database operations target under 200 ms. Folder enumeration measures local request timing separately from Google remote latency and exposes a recoverable unavailable result.

## Acceptance criteria and test matrix

| Criterion | Test layer | Evidence |
| --- | --- | --- |
| Given an active Admin and configured provider, when OAuth starts, then it redirects to Google with a one-time state bound to that Admin/session/organization and only the read-only scope. | API + unit | Fake port assertion; no state/cookie/token leak. |
| Given a matching OAuth callback, when Google returns credentials, then a source belongs to the initiating organization and stores ciphertext only. | API + PostgreSQL | Callback/idempotency/encryption test. |
| Given a missing, expired, replayed or mismatched OAuth state, when callback occurs, then it fails generically without exchanging code or creating a source. | API negative | State lifecycle test. |
| Given an Owner/Admin source, when folders are listed or selected with eligibility confirmation, then only same-organization records are visible and a workspace folder is created once per external id/source. | API + PostgreSQL | Positive and unique-scope test. |
| Given Member or another organization, when accessing a source/folder, then no record is returned or changed. | Authorization negative | Role and cross-tenant tests. |
| Given remote unauthorized credentials, when a provider call fails, then source becomes `reauth_required` and no new sync is enqueued. | Unit + integration | Status transition/log-redaction test. |
