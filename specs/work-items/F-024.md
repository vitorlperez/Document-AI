# F-024 - Área de ferramentas e gestão da conexão Google Drive

**Status:** validating

## Source and outcome

- Source specification: `specs/001-mvp-document-intelligence.md` F2, section 7 (security/privacy) and F-017 reauthorization behavior.
- User outcome: the current integrations route becomes a generic **Tools** catalog. Selecting Google Drive opens a management modal that identifies the authorized Google account when available, exposes its connection state, supports reauthorization, and safely disconnects it so another account can later be authorized.
- Non-goals: a second external connector, changing Drive OAuth scope, deleting indexed Company knowledge on disconnect, revoking access from Google remotely, or changing workspace/RAG access rules.

## Decisions

| Decision | Owner | Status | ADR / rationale |
| --- | --- | --- | --- |
| Use Drive `about.get` with the existing `drive.readonly` grant to capture only the authorized account e-mail after OAuth completion | Product + implementation | approved | The Google method accepts the current scope; the e-mail makes the account action understandable without expanding consent |
| Persist the authorized account e-mail as connection metadata and return it only to Owner/Admin within its organization | Product + implementation | approved | Required for the requested connection modal; no token or document content is exposed |
| Disconnect clears locally retained encrypted credentials and account metadata, marks the source `disconnected`, and retains existing indexed snapshots | Product + implementation | approved | Existing specification requires only that future syncs stop; removing knowledge is a separate destructive action |
| Reauthorization reuses the source UUID and may authorize a different Google account | Product + implementation | approved | Keeps workspace/source links stable while requiring the new account to authorize access before further syncs |
